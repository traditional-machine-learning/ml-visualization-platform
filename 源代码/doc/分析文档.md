# 机器学习算法仿真实验与学习平台 · 分析文档

> **阶段说明：** 本文以当前仓库 `master` 分支代码和配置为准。第一阶段《需求规格说明书》仅用于说明项目早期背景与需求来源；第二阶段的开发范围和实现方式有所调整，并未完全按该说明书逐项实施。历史需求不能代替代码验证，也不能据此推断某项功能已经交付。

## 1. 项目定位

本平台是面向机器学习初学者的**教学辅助工具**，不是生产级建模工具。由此确定三条设计原则：

| 原则 | 含义 | 对实现的约束 |
|---|---|---|
| 直观性 | 抽象优化过程必须画得出来 | 每步训练都要产出几何量（线、质心、树节点），不能只给一个 loss 数字 |
| 交互性 | 用户能干预训练过程 | 训练必须可拆步、可暂停、可续训，且状态要能持久化 |
| 引导性 | 有配套的学习材料 | 课程、案例、指标解释、AI 答疑四者闭环 |

一句话概括取舍：**宁可算法实现简化，也要保证「看得见、动得了、讲得清」**。

### 1.1 第一阶段需求背景与第二阶段范围说明

第一阶段《需求规格说明书》记录了项目早期的改进方向，主要覆盖界面与交互、实验记录、参数与教学、模型对比、算法功能、数据集管理六个领域。它反映了项目最初希望解决的问题，也有助于理解平台为何逐步增加训练可视化、学习引导和实验辅助能力。

但第二阶段并未完全按照第一阶段说明书逐项实施，实际开发过程中对功能范围和实现方式进行了调整。因此，本分析不把第一阶段的需求清单视为第二阶段的验收清单；下文的功能状态、技术实现和缺口判断均以当前仓库代码为依据。需求文档中曾经提出、但当前代码未实现的能力，不计入当前完成项。

## 5. 非功能需求

### 5.1 易用性

- 首屏自动加载默认案例，用户不需要先理解「选什么算法」；
- 每个面板有明确标题与空态文案，训练未开始时提示「选择算法、数据集或引导式案例以开始」；
- 参数控件带默认值与范围，避免输入非法值（后端仍会 clamp 兜底）。

### 5.2 稳定性

| 风险 | 处置 |
|---|---|
| 远程数据集下载失败 | 只记日志，保留演示数据 |
| 数据库为空/表缺失 | 启动即报错（属于配置问题，必须暴露） |
| 前端目录接口失败 | 自动切 mock 数据并提示 |
| 训练请求失败 | 状态回退为 idle/paused，横幅提示 |
| 上一步未返回又发下一步 | `stepInFlight` 拦截 |
| 慢响应覆盖新状态 | `requestVersion` + `sessionId` 双重校验 |

### 5.3 可维护性

- 算法实现与 HTTP/DB 解耦，输入只有 `Dataset + parameters + ModelData`；
- DTO 与实体分离，接口契约稳定；
- `schema.sql` 可重复执行，环境重建成本低；
- 文档（本文档 + 设计 + 开发 + 部署 + 使用 + 设计模式分析）与代码同步维护。

### 5.4 性能

| 场景 | 当前策略 | 量级 |
|---|---|---|
| 轮廓系数计算 | 采样估算，避免 O(n²) | 150 样本即时 |
| PCA | 幂迭代求前 k 个特征向量 | 13 维 506 样本 < 100ms |
| 训练步进 | 每步一次 HTTP + 一次 UPDATE | 850ms 间隔，无压力 |
| 数据集传输 | 列表接口只传两维点，详情才带全维度 | 列表响应体约为详情 1/10 |

## 6. 系统边界

### 6.1 功能边界

| 范围内 | 范围外 |
|---|---|
| 传统 ML：线性/逻辑回归、决策树、随机森林、K-Means、SVM、PCA | 深度学习、神经网络、GPU 训练 |
| 小规模教学数据（百级样本、十几维） | 大规模数据、分布式计算 |
| 简化教学实现（采样轮廓系数、近似核 SVM） | 生产级高性能实现（scikit-learn 级别） |
| 单用户本地/演示部署 | 多租户、权限体系、并发训练调度 |
| 训练过程与结果的可视化解释 | 自动建模、AutoML、模型上线服务 |

### 6.2 技术边界

- 前端固定在 Angular 生态，可视化固定在 ECharts；
- 后端固定 Spring Boot + MyBatis，不引入 JPA；
- 算法在 JVM 内实现，不调用 Python 科学计算库；
- 部署以 Docker Compose 为准，不依赖 K8s 等编排。

### 6.3 能力边界（必须向用户说清）

| 边界 | 表现 |
|---|---|
| SVM 只在两维训练 | 切换坐标轴时不出边界，界面给出提示 |
| 随机森林树数上限 20 | `n_estimators` clamp |
| 轮廓系数为采样估算 | 数值接近但非精确 |
| PCA 主成分上限 3 | 受 3D 可视化表达限制 |
| AI 助手依赖外部服务 | 无 Key 时不可用 |

## 7. 数据需求

### 7.1 数据集

| 数据集 | 维度 | 样本 | 标签类型 | 用途 |
|---|---|---:|---|---|
| iris | 4 数值 + species | 150 | 文本类别 | 分类、聚类、树结构 |
| boston_housing | 13 数值 + medv | 506 | 数值目标 | 回归、权重解释 |
| make_classification | 2 数值特征 + 数值标签 | 100 | 二分类（0/1） | 二维边界演示 |
| make_blobs | 2 数值 | 150 | 无（有簇编号） | 聚类演示 |

### 7.2 数据规格要求

| 约束 | 说明 |
|---|---|
| 特征列必须可转 double | 无法解析的行在填充时被丢弃 |
| 标签列 `type=label` | 决定目标值取哪一列；不参与特征矩阵 |
| CSV 表头与 `features[].name` 一致 | 不一致则整份数据被跳过并打日志 |
| 样本量百级 | 浏览器渲染与逐步训练的时间可控 |

### 7.3 数据存储

- 维度元数据与行数据都存 JSON 列，避免为不同数据集建宽表；
- 训练快照存 `training_session.model_data`，指标序列存 `metrics`；
- 学习中心数据（课程、题库）不落库，随前端打包。

## 9. 缺口与后续计划

| 优先级 | 缺口 | 建议方案 |
|---|---|---|
| 高 | CSV 上传未解析 | 复用 `DatasetSeedInitializer.parseCsv`，上传即解析入库 |

| 低 | 对比串行执行 | 并发或批量接口 |
| 低 | 无用户体系 | 引入轻量登录后可做学习进度云端同步 |

## 10. 结论

> **安全提醒：** 当前公开仓库的配置文件中存在明文数据库凭据和大模型 API Key。此问题不属于文档层面的功能实现，应由仓库维护者轮换凭据并改用安全配置方式；本文不复制具体密钥。

1. **当前代码已形成主要教学实验闭环**：算法与数据集选择、参数配置、逐步训练、过程可视化、学习课程与案例等主要模块已有对应实现；但这不等于第一阶段《需求规格说明书》中的所有需求都已完成，也不代表第二阶段逐项按该说明书实施。
2. **超出原始需求的扩展**：全维度投影、三维 PCA、学习中心与题库、模型快照续训、降级演示模式，显著提升了教学可用性。
3. **明确的能力边界已如实标注**：SVM 两维训练、树数上限、采样轮廓系数等，都是可解释的取舍而非缺陷。
4. **仍有明确功能缺口和技术债**：CSV 上传尚未完成解析入库，单样本预测与模型结构接口仍为占位实现，当前没有历史实验检索页面，也没有用户登录体系；云服务器部署尚未验证。`TrainingSimulationService` 体积较大、算法分派逻辑重复，仍需后续重构。

# 机器学习算法仿真实验与学习平台 · 使用文档

> **阶段说明：** 本文以当前仓库 `master` 分支代码和配置为准。第一阶段《需求规格说明书》仅用于说明项目早期背景与需求来源；第二阶段的开发范围和实现方式有所调整，并未完全按该说明书逐项实施。历史需求不能代替代码验证，也不能据此推断某项功能已经交付。

## 1. 项目简介

本项目是一个面向传统机器学习算法学习与实验的 Web 平台，采用 **Spring Boot 后端 + Angular 前端 + MySQL 数据库** 的前后端分离架构，支持 Docker 一键启动。

平台分为两个页面：

| 页面 | 路由 | 定位 |
|---|---|---|
| **训练中心** | `/experiment` | 选算法、配参数、控制训练、观察可视化与指标 |
| **学习中心** | `/learn` | 8 节理论课程、随堂自测、理论考核与错题集 |

两个页面通过顶部导航切换。页面状态会被保留：从训练中心切到学习中心再切回来，训练进度、当前课节、答题记录都不会丢失。

项目仓库地址：

```text
https://github.com/traditional-machine-learning/ml-visualization-platform
```

## 2. 三种运行方式

### 2.1 方式一：Docker 运行（推荐）

该方式会同时启动 MySQL、Spring Boot 后端和 Nginx + Angular 前端，不需要单独安装 JDK / Node.js / MySQL。

**环境要求**

- Docker Desktop（或 Docker Engine）
- Docker Compose v2

**获取代码并启动**

```bash
git clone https://github.com/traditional-machine-learning/ml-visualization-platform.git
cd ml-visualization-platform/源代码
docker compose up --build
```

后台运行：

```bash
docker compose up -d --build
```

启动完成后访问：

```text
http://localhost/
```

**说明**

- 三个容器分别为 `ml-platform-mysql`、`ml-platform-backend`、`ml-platform-frontend`。
- 前端容器内的 Nginx 把 `/api/` 反向代理到 `backend:8080`，因此浏览器只需访问一个端口。
- Docker 模式下不需要再单独执行 `npm start` 或 `mvn spring-boot:run`。
- 首次启动时后端会执行 `schema.sql` 建表并写入演示数据，再由 `DatasetSeedInitializer` 补齐完整数据集（见 2.4）。

### 2.2 方式二：本地前后端分别启动

适合开发调试。

**环境要求**

| 工具 | 建议版本 | 用途 |
|---|---:|---|
| JDK | 17+ | 运行 Spring Boot |
| Maven | 3.8+ | 构建后端 |
| Node.js | 18+ | 运行 Angular |
| MySQL | 8.0+ | 保存算法、数据集、训练会话 |

**第一步：准备数据库**

```bash
mysql -u root -p < backend/src/main/resources/schema.sql
```

`schema.sql` 会自动创建 `ml_platform` 库、三张表以及全部预置算法与数据集演示数据，可重复执行（内部使用 `IF NOT EXISTS` / `INSERT IGNORE` 与去重语句）。

**第二步：修改后端配置**

编辑 `backend/src/main/resources/application.yml`，把数据源指向本机 MySQL：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/ml_platform?useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useUnicode=true&characterEncoding=UTF-8
    username: root
    password: 你的密码
```

**第三步：启动后端**

```bash
cd backend
mvn spring-boot:run
```

后端地址：`http://localhost:8080`

**第四步：启动前端**

```bash
cd frontend
npm install
npm start
```

前端地址：`http://localhost:4200`，实验页为 `http://localhost:4200/experiment`。

本地开发模式下 `npm start` 会带上 `--proxy-config proxy.conf.json`，把 `/api` 请求转发到 `localhost:8080`，因此必须先启动后端。

### 2.3 方式三：云服务器部署（可选操作指南，非当前已上线服务）

当前仓库提供 Docker Compose 配置，但这不代表项目已经部署到云服务器或拥有公网演示地址。若后续需要自行部署，可在先处理数据库端口和凭据安全问题后，按《部署文档》操作。在服务器上安装 Docker 与 Docker Compose 后，上传项目并执行：

```bash
cd ml-visualization-platform/源代码
docker compose up -d --build
```

按部署文档调整端口映射、防火墙和凭据后，才可通过服务器地址访问。当前配置没有提供 HTTPS/TLS 终止，也没有可确认的公网演示地址。详细步骤见《部署文档》。

> 云端演示地址以实际部署为准；若无法访问，请使用方式一或方式二在本地运行。

### 2.4 关于数据集自动填充

内置数据集并不全部以完整形式存在数据库里，启动时由 `DatasetSeedInitializer`（`service/DatasetSeedInitializer.java`）按需补齐：

| 数据集 | 填充方式 | 说明 |
|---|---|---|
| `iris` | 从远程 CSV 下载 | 需要能访问外网；失败则保留演示数据 |
| `boston_housing` | 从远程 CSV 下载 | 同上 |
| `make_classification` | 程序生成（两个高斯簇） | 随机种子固定为 42，结果可复现 |
| `make_blobs` | 程序生成（三个高斯簇） | 同上 |

填充是**幂等**的：只有当表内已有条数少于目标条数时才执行。若下载失败，只记录日志、保留 `schema.sql` 里的演示数据，不影响应用启动。

需要代理才能访问外网时，可以给后端设置环境变量（优先级最高）：

```bash
# Linux / macOS
export DATASET_SEED_PROXY=http://127.0.0.1:7890
# 或者
export HTTPS_PROXY=http://127.0.0.1:7890
```

Docker 环境可参考部署文档在 `docker-compose.yml` 中为 backend 添加 `HTTPS_PROXY=http://host.docker.internal:7890`。

## 3. 训练中心使用说明

### 3.1 页面布局

| 区域 | 内容 |
|---|---|
| 顶部 | 标题、「训练中心 / 学习中心」导航 |
| 左侧栏 | 算法选择、数据集选择、模型对比、特征工程 |
| 中间 | 可视化画布（坐标轴选择器 + 图表）、评估指标面板 |
| 右侧栏 | 参数配置、训练控制、训练日志、模型解释 |
| 页面下方 | 实验案例库 |
| 右下角 | AI 助手悬浮窗 |

### 3.2 选择算法与数据集

打开页面时会自动从后端加载算法与数据集列表，并默认加载「解释线性回归器」引导案例。

**支持的算法**

| 算法 | 类别 | 可调参数 | 单步训练的含义 | 训练步数 |
|---|---|---|---|---|
| 线性回归 `linear_regression` | 监督 / 回归 | 学习率、迭代次数 | 一次梯度下降更新 | `iterations` |
| 逻辑回归 `logistic_regression` | 监督 / 分类 | 学习率、迭代次数、正则化系数 | 一次梯度下降更新 | `iterations` |
| 决策树 `decision_tree` | 监督 / 分类 | 最大深度、最小分裂样本数、分裂准则 | 展开一个节点（一次分裂） | 树的实际分裂数 |
| K 均值聚类 `kmeans` | 无监督 / 聚类 | 聚类数 K、最大迭代次数、初始化方法 | 一轮「分配 + 更新中心」 | `maxIterations` |
| 支持向量机 `svm` | 监督 / 分类 | 核函数、C、gamma、迭代次数 | 一次边界优化迭代 | `iterations` |
| 随机森林 `random_forest` | 监督 / 集成 | 树的数量 | 训练一棵新的树 | `n_estimators` |
| PCA `pca` | 无监督 / 降维 | 主成分数（1~3） | 一次性算完，无逐步过程 | 记为 k/k |

**支持的数据集**

| 数据集 | 类别 | 维度 | 样本数 | 用途 |
|---|---|---|---:|---|
| 鸢尾花 `iris` | 监督 | 4 个数值特征 + 种类标签 | 150 | 分类、聚类、决策树结构演示 |
| 波士顿房价 `boston_housing` | 监督 | 13 个数值特征 + 房价目标 | 506 | 回归、线性权重解释 |
| 合成分类 `make_classification` | 监督 | 2 个数值特征 + 数值标签（0/1） | 100 | 二维决策边界的直观演示 |
| 合成聚类 `make_blobs` | 无监督 | 2 个数值特征（带簇编号） | 150 | 聚类中心与簇结构演示 |

> 两个合成集都只有两个维度，因此在画布上可以直接看到完整的模型形态，适合课堂讲解。
> 分类集的标签列取值是 `0/1`（数值型标签），回归算法也能把它当作连续目标使用。

### 3.3 选择坐标轴（多维数据的关键操作）

真实数据集有 4~13 个维度，但画布只能显示二维平面。可视化画布左上角提供 **X 轴 / Y 轴下拉选择器**：

- 切换坐标轴后，数据点会按所选的两个维度重新取坐标；
- 模型叠加层也会随之重新计算（调用后端的投影接口），而不是简单地把原来的线搬过去；
- 线性回归 / 逻辑回归 / K-Means 的模型是**全维度**训练的，投影到任意两维都是真实切片；
- 决策树按全维度训练，可在所选二维平面上绘制已展开节点对应的分区线段；随机森林也使用全维度特征，但当前不计算二维决策分区线，只按样本预测类别着色；
- SVM 仍在两维上训练，切换到非训练维度时画布会给出提示，不显示边界。

PCA 视图下不显示坐标轴选择器，因为坐标轴本身就是主成分。

### 3.4 配置参数

右侧「参数配置」面板根据所选算法的 `parameters` 定义动态生成：

- 数值参数：滑块 + 数值输入，带默认值、最小值、最大值、步长；
- 选择参数：下拉框（如 SVM 核函数 `linear / rbf / poly`、决策树准则 `gini / entropy`）；
- 「恢复默认」按钮可把全部超参数恢复为定义中的默认值，不会打断正在进行的训练。

参数变更会立即刷新步数、评估面板和解释面板。

### 3.5 控制训练

| 按钮 | 行为 |
|---|---|
| **开始** | 未开始则创建会话并进入连续训练（每 850ms 推进一步）；已暂停则继续 |
| **暂停** | 停止定时推进，并把当前模型状态评估一次写入会话 |
| **继续** | 在同一个会话上继续推进，不重新初始化模型 |
| **重置** | 清空会话与训练日志，回到「未开始」状态 |
| **单步执行** | 只推进一步，便于观察参数变化；未开始训练时会先创建会话 |

训练过程中，按钮区下方显示「当前步数 / 总步数」和当前得分。

**状态流转**：`idle → training ⇄ paused → completed`

- 单步执行后状态置为 `paused`，不会自动继续；
- 达到总步数后自动置为 `completed`；
- PCA 是一次性计算，点击「开始」后直接进入 `completed`。

### 3.6 观察可视化

| 任务类型 | 画布内容 |
|---|---|
| 分类 | 散点（按标签着色）+ 决策边界；决策树显示轴对齐的分区线，随机森林按预测类别为样本着色、不绘制二维分区线 |
| 回归 | 散点 + 回归线 |
| 聚类 | 散点（按簇着色）+ 聚类中心 |
| 降维（PCA） | 主成分平面散点；主成分数选 3 时显示自绘 Canvas 三维散点视图，可用鼠标拖拽旋转 |
| 随机森林 | 特征重要性条形图 |

训练未开始时，画布只显示数据点与坐标轴，不会预先画出「假」的模型曲线。

### 3.7 查看评估指标

评估面板的标题会随任务类型变化（回归质量 / 聚类指标 / 评估指标），核心是两张指标卡 + 一条双轴曲线：

| 任务 | Loss 轴 | Score 轴 |
|---|---|---|
| 回归 | `MSE` | `R2` |
| 分类 | `Loss`（逻辑回归交叉熵）/ `Gini`（决策树）/ `Hinge Loss`（SVM）/ `Error`（随机森林） | `Accuracy` |
| 聚类 | `Inertia` | `Silhouette` |
| PCA | 无数值损失 | `ExplainedVar`（累计方差解释率） |

指标卡上的 `delta` 是「与上一步相比的真实变化量」，训练未开始时卡片只显示标签、不显示数字。PCA 还会额外展示方差解释率、累计解释率、载荷矩阵以及每个主成分的自动含义标签（如「petal 正向综合轴」）。

### 3.8 查看模型解释

| 算法 | 解释形式 |
|---|---|
| 决策树 | 树结构：节点分裂条件、深度、样本数、类别纯度，随训练逐步展开 |
| 线性回归 / 逻辑回归 | 特征权重横向条形图（正负分色） |
| K-Means | 聚类中心与簇规模摘要 |
| SVM | 支持向量与分离边界摘要 |
| PCA | 主成分摘要 + 载荷矩阵 |

### 3.9 使用实验案例库

页面下方提供 5 个引导案例，点击卡片会自动切换算法、数据集和预设参数：

| 案例 | 算法 | 数据集 | 学习目标 |
|---|---|---|---|
| 使用 K-Means 聚类 Iris 数据 | K-Means | 合成聚类 | 观察 K 值与簇紧凑性 |
| 分类合成数据点 | 逻辑回归 | 合成分类 | 观察决策边界与特征权重方向 |
| 解释决策树 | 决策树 | 鸢尾花 | 读懂分裂条件与节点纯度 |
| 解释线性回归器 | 线性回归 | 波士顿房价 | 理解权重与损失下降 |
| 比较边界分类器 | SVM | 合成分类 | 理解间隔与核函数 |

案例卡片会显示当前引导阶段：加载预设 → 检查设置 → 运行训练 → 查看指标 → 验证结果。

### 3.10 模型对比

左侧「模型对比」可以添加多个配置（同一数据集、不同算法或不同参数），点击对比后：

- 每个配置都会真实训练到收敛，返回最终指标；
- 结果以柱状图展示，可切换比较 `accuracy` 或 `loss`；
- 可给每个配置起别名，便于区分「C=0.1」与「C=10」。

### 3.11 特征工程

左侧「特征选择」可以勾选/排除数据集的维度，然后执行一次评估，观察指标变化。切换数据集时会通过详情接口拉取全维度元数据，因此可以在任意维度上做选择；标签列由后端自动保留。

### 3.12 使用 AI 助手

右下角悬浮球打开 AI 助手，提问时会自动携带当前上下文：算法名称与描述、数据集、训练状态、当前步数、损失与准确率、参数。

**使用前提**：后端必须配置大模型 API Key（见部署文档）。未配置时助手会返回：

```text
AI API key not configured. Please set LLM_API_KEY environment variable.
```

## 4. 学习中心使用说明

### 4.1 课程

左侧为课程目录，共 8 节，分四组：

| 分组 | 课程 |
|---|---|
| 入门基础 | 机器学习简介、机器学习工作流程 |
| 学习类型 | 监督学习 |
| 监督学习 | 线性回归、逻辑回归与分类、决策树 |
| 无监督 / 评估 | K-Means 聚类、模型评估指标 |

每节课包含：摘要、分步讲解、要点清单、生活中的例子、随堂自测（选择 + 解析）。侧边栏顶部显示学习进度百分比，读完一节点「标记完成」即可推进进度。

### 4.2 理论考核

「理论考核」每次随机抽 5 题（题库共 200 题：40 个知识点 × 5 种问法），每题 20 分，满分 100。提交后才能看到解析。

### 4.3 错题集

答错的题目会进入错题集，并保存在浏览器 `localStorage`（键名 `ml-learning-wrong-questions`）。错题集里可以「只考错题」重新练习，答对的题目仍会保留在错题集中供复习。

## 5. 常见问题

### 5.1 Docker 报 `dockerDesktopLinuxEngine` 连接失败

Docker Desktop 未启动或引擎未就绪。启动 Docker Desktop，等状态变为 Running 后重试。

### 5.2 3306 端口被占用

本机已有 MySQL 占用 3306。可以停止本机 MySQL，或改用本地前后端分开启动的方式。

### 5.3 后端启动报数据库连接失败

检查 `application.yml` 中的 `url / username / password`，确认库已创建：

```bash
mysql -u root -p -e "SHOW DATABASES LIKE 'ml_platform';"
```

### 5.4 前端请求 `/api` 返回 HTML（`Unexpected token '<'`）

说明请求命中了前端路由而不是后端接口。请确认：

- 本地开发使用 `npm start` 启动（带 `proxy.conf.json`），不要用静态服务器打开 `dist`；
- 后端 `http://localhost:8080` 已启动；
- Docker 方式访问 `http://localhost/`，不要访问 `4200`。

### 5.5 页面提示「API 不可用，已切换到本地演示数据」

前端加载算法/数据集失败时会自动降级为内置演示数据（`LearningGuideDataService` 中的 mock 数据）。此时训练不会真正调用后端，指标是按进度合成的曲线，仅用于界面演示。检查后端日志与网络面板定位原因。

### 5.6 数据集样本数比预期少

说明启动时远程 CSV 下载失败，保留了演示数据。查看后端启动日志中的 `[数据集填充]` 记录；如需代理，请设置 `DATASET_SEED_PROXY` 或 `HTTPS_PROXY`。

### 5.7 训练一直停在 0 步 / 点开始没反应

- 未选择算法或数据集时按钮是禁用的；
- 后端返回失败时状态会回退为 `idle` 或 `paused`，页面顶部会提示「训练请求失败」；
- 检查 `training_session` 表是否可写。

### 5.8 切换坐标轴后看不到决策边界

SVM 只在两个维度上训练，切到其他维度时不会回放几何结果，画布会显示提示文字。这是设计上的取舍，不是故障。

## 6. 已知限制

> **安全提醒：** 当前公开仓库的 `application.yml` 和 `docker-compose.yml` 含有明文凭据配置（数据库凭据及大模型 API Key）。不要在文档、截图或新提交中复制这些值；仓库维护者应尽快轮换已暴露凭据，并改为环境变量或密钥管理方式。本文不展示任何真实凭据。

以下功能在当前代码中尚未落地，文档如实记录，便于后续迭代：

| 功能 | 现状 |
|---|---|
| CSV 数据集上传 | 前端 `onFileUpload` 目前只在控制台打印文件名，没有调用上传 API；后端 `POST /api/datasets/upload` 即使被直接调用也只保存元信息，不解析 CSV 内容 |
| 单样本预测 | `POST /api/algorithms/{id}/predict` 为占位接口，返回固定字符串 |
| 模型结构接口 | `GET /api/visualization/model-structure/{sessionId}` 为占位接口；当前训练中心的模型解释面板使用训练响应中的 `modelData`，并不依赖该占位接口 |
| AI 助手 | 需要外部大模型 API Key；未配置时只返回错误提示 |
| 实验历史 | 训练会话会写入 `training_session`，但当前没有历史会话列表/检索页面，不能把数据库留存等同于完整的历史实验管理功能 |
| 用户与权限 | 无登录体系，训练会话按数据库自增 ID 区分 |
| 训练历史回看 | `training_session` 表保留历史会话，但界面只使用当前会话 |

# 机器学习算法仿真实验与学习平台 · 设计文档

> **阶段说明：** 本文以当前仓库 `master` 分支代码和配置为准。第一阶段《需求规格说明书》仅用于说明项目早期背景与需求来源；第二阶段的开发范围和实现方式有所调整，并未完全按该说明书逐项实施。历史需求不能代替代码验证，也不能据此推断某项功能已经交付。

## 1. 系统概述

### 1.1 设计目标

| 目标 | 设计手段 |
|---|---|
| 让优化过程「看得见」 | 训练可拆成可观察的逐步过程，每步都产出可视化所需的几何数据 |
| 让用户能「动手干预」 | 开始 / 暂停 / 继续 / 单步 / 重置五态控制，参数随时可调 |
| 让多维数据「画得下」 | 全维度训练 + 任意两维切片投影，而不是把高维数据砍成两列 |
| 让学习有「配套材料」 | 引导案例 + 8 节理论课 + 200 题考核 + 错题集 |
| 让演示「不会崩」 | 后端异常只降级不阻断；前端 API 不可用时切本地演示数据 |

### 1.2 技术架构

前后端分离的 B/S 架构，三层容器化部署。

| 层 | 技术 | 版本 | 说明 |
|---|---|---|---|
| 表现层 | Angular + Angular Material | 17.3 | NgModule 组件化，SCSS 主题 |
| 可视化 | ECharts + Canvas 2D | ECharts 6.0 | ECharts 绘制二维图表；PCA 三维散点由原生 Canvas 2D 自绘并支持拖拽旋转 |
| 接口层 | Spring Boot Web | 3.2.0 | RESTful JSON |
| 业务层 | Spring Service | 3.2.0 | 算法仿真、会话管理、数据集投影 |
| 持久层 | MyBatis | 3.0.3 | 注解 SQL，动态代理生成实现 |
| 存储 | MySQL | 8.0 | 三张表，JSON 列存快照 |
| 部署 | Docker Compose | v2 | mysql / backend / frontend 三容器 |

### 1.3 角色与场景

系统无登录体系，面向单一角色「学习者」，典型场景：

1. **跟课学习**：在学习中心读课程 → 做随堂自测 → 到训练中心复现课程里的实验；
2. **案例实验**：从案例库加载预设配置 → 单步观察模型演化 → 对照验证标准；
3. **自由探索**：自选算法与数据集 → 调参对比 → 用模型对比量化差异；
4. **求助答疑**：把当前实验上下文交给 AI 助手提问。

### 2.2 后端分层

```
Controller 层    AlgorithmController / DatasetController / VisualizationController
                 ComparisonController / FeatureEngineeringController / AiAssistantController
                 —— 参数搬运、ApiResponse 包装、HTTP 状态语义
        │
Service 层       TrainingSimulationService（算法仿真 + 会话 + 投影）

        │

        │

```

关键约束：

- Controller 不写业务，Service 不拼 HTTP 响应，Repository 不写业务分支；
- 实体不直接出网关，一律转 DTO（`AlgorithmDTO`、`DatasetDTO`）；
- 异常统一由 `GlobalExceptionHandler` 转换：`IllegalArgumentException → 400`，其余 `→ 500`。

## 3. 数据库设计

### 3.1 实体关系

```
algorithm 1 ──── n training_session n ──── 1 dataset
```

`training_session.algorithm_id` / `dataset_id` 均为外键，删除被引用的算法或数据集会失败——这是有意的：训练历史必须可追溯。

### 3.2 dataset

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK, AI | — |
| name | VARCHAR(100) | NOT NULL, UNIQUE | 英文标识，案例与前端按它匹配 |
| description | TEXT | — | 中文说明 |
| category | VARCHAR(50) | NOT NULL | supervised / unsupervised |
| file_name | VARCHAR(255) | — | 上传来源文件名 |
| feature_count | INT | — | 数值特征数（不含 label 列） |
| sample_count | INT | — | 实际行数 |
| features | JSON | — | 维度元数据 |
| data_content | JSON | — | 行对象数组 |
| created_at | TIMESTAMP | DEFAULT NOW | — |

`features` 元素结构：`{"name","displayName","type"}`，`type ∈ {number, label}`。标签列用于取目标值，不参与特征矩阵。

`data_content` 元素是「列名 → 值」的对象，例如：

```json
{"sepal_length":5.1,"sepal_width":3.5,"petal_length":1.4,"petal_width":0.2,"species":"setosa"}
```

用对象而不是数组，好处是列顺序变化、缺列都不影响读取；代价是存储略大（教学数据量可接受）。

### 3.3 algorithm

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK, AI | — |
| name | VARCHAR(100) | NOT NULL, UNIQUE | `linear_regression` 等，代码分派依据 |
| display_name | VARCHAR(100) | NOT NULL | 中文名 |
| description | TEXT | — | 算法简介，AI 助手上下文也用它 |
| category | VARCHAR(50) | NOT NULL | supervised / unsupervised |
| type | VARCHAR(50) | NOT NULL | regression / classification / clustering / pca / ensemble |
| parameters | JSON | — | 参数定义数组 |
| created_at | TIMESTAMP | DEFAULT NOW | — |

`parameters` 元素支持两种控件：

```json
{"name":"learningRate","displayName":"学习率","type":"number","default":0.01,"min":0.0001,"max":1,"step":0.0001}
{"name":"kernel","displayName":"核函数","type":"select","default":"rbf","options":["linear","rbf","poly"]}
```

### 3.4 training_session

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PK, AI | 会话 ID |
| algorithm_id | BIGINT | NOT NULL, FK | — |
| dataset_id | BIGINT | NOT NULL, FK | — |
| parameters | JSON | — | 本次训练的归一化参数 |
| status | VARCHAR(50) | DEFAULT 'idle' | idle/training/paused/completed |
| current_step | INT | DEFAULT 0 | 已推进步数 |
| total_steps | INT | DEFAULT 100 | 总步数（决策树会回填） |
| metrics | JSON | — | `{points:[{step,loss,score}],lossLabel,scoreLabel}` |
| model_data | JSON | — | 模型快照（权重、质心、树、PCA…） |
| created_at | TIMESTAMP | DEFAULT NOW | — |
| updated_at | TIMESTAMP | ON UPDATE NOW | 每次 step 刷新 |

**为什么把模型序列化成 JSON 存库**：服务端必须无状态（水平扩容、重启不丢训练），而模型结构随算法变化（线性是权重、K-Means 是质心、树是节点表）。JSON 列 + `ModelData` 统一结构，既满足无状态要求，又不用为每种算法建表。

### 3.5 预置数据

| 类型 | 数量 | 明细 |
|---|---:|---|
| 算法 | 7 | linear_regression、logistic_regression、decision_tree、kmeans、svm、pca、random_forest |
| 数据集 | 4 | iris(4 维/150)、boston_housing(13 维/506)、make_classification(2 维/100)、make_blobs(2 维/150) |

`schema.sql` 可重复执行：建表用 `IF NOT EXISTS`，插入用 `INSERT IGNORE`，并对 `dataset.name` 先做去重再加唯一索引；末尾的 `UPDATE` 语句负责把 `svm`、`pca` 的参数定义刷新到最新形态。

真实数据（iris / boston）的完整样本由 `DatasetSeedInitializer` 在启动时补齐：

```
run()
 ├─ 遍历 remote-sources：findByName → countRows
 │     ├─ 已有 ≥ expectedSamples → 跳过（幂等）
 │     └─ 不足 → 下载 CSV → 按 features 表头对齐解析 → saveRows
 ├─ 遍历 synthetic-samples：条数不足 → 生成高斯簇数据 → saveRows
 └─ 任一步异常仅 log.warn，保留原数据
```

## 4. 模块设计

### 4.1 可视化建模模块

| 子模块 | 输入 | 处理 | 输出 |
|---|---|---|---|
| 算法选择 | 后端算法列表 | 分组展示，缺 `pca` 时补占位项 | 选中算法 + 参数默认值 |
| 数据集选择 | 数据集列表 | 列表接口给两维投影；选中后再拉详情接口补全维度 | 选中数据集（含 `dimensions`） |
| 参数配置 | `ParameterDef[]` | `number` → 滑块 + 输入框；`select` → 下拉 | 参数值字典 |
| 可视化画布 | 数据集 + 算法 + 训练态 | 按 `modelKind` 分支渲染；坐标轴变化时请求投影 | ECharts option |

**坐标轴选择的设计**：画布持有 `selectedXName / selectedYName`，变化时：

```
onAxisChange()
  ├─ 若为 PCA 视图 → 忽略（轴即主成分）
  ├─ 若训练中/已完成 → GET /visualization/projection/{sessionId}?xName&yName
  └─ 否则只按新维度重算散点坐标（无模型叠加层）
```

投影结果按「会话 + 坐标轴 + 模型版本」去重（`viewKey()` 生成 `sessionId|X|Y`，再加上 `modelRevision` 作为请求键），响应再用 `projectionVersion` 丢弃过期结果，避免快速拖动下拉框导致的错序渲染。

### 4.2 训练控制模块

**五态控制**

| 动作 | 前置状态 | 后端调用 | 结果状态 |
|---|---|---|---|
| 开始 | idle | `POST /train` | training（定时器启动） |
| 暂停 | training | `POST /pause` | paused |
| 继续 | paused | `POST /step`（复用会话） | training |
| 单步 | idle / paused / training | `POST /train` 或 `/step` | paused 或 completed |
| 重置 | 任意 | 无 | idle，清日志 |

**并发控制**（前端）

| 机制 | 解决问题 |
|---|---|
| `requestVersion` 单调递增 | 暂停后旧的 step 响应晚到，会覆盖新状态 |
| `stepInFlight` 互斥 | 850ms 定时器比请求往返更快时，请求堆积导致步数跳变 |
| `sessionId` 比对 | 重置后旧会话响应污染新会话 |
| 后端 `validateSession` | 防止用 A 算法的 sessionId 调 B 算法的 step 接口 |

**单步语义（后端）**

| 算法 | 一步的含义 | 为什么这样切 |
|---|---|---|
| 线性回归 / 逻辑回归 | 一次梯度更新 | 直观展示学习率对收敛轨迹的影响 |
| K-Means | 一轮「分配 + 重算中心」 | 展示质心移动与簇归属变化 |
| 决策树 | 展开一个节点 | 展示树如何「长」出来，而不是一次性给出结果 |
| 随机森林 | 增加一棵树 | 展示集成误差随树数下降 |
| SVM | 一次边界优化迭代 | 展示间隔推挤过程 |
| PCA | 无（一次算完） | 特征分解没有可观察的中间态 |

**决策树增量展开的实现**：完整贪心树在首次需要时**一次建完**并存入 `modelData.tree`，每个节点带 `splitOrder`（BFS 序号）；训练时只把 `revealedSplits` 加一，`applyTreeState` 按当前阈值把未展开节点当叶子处理。这样「暂停在最近一次分裂」是精确的，也不必每次重建树。

**随机森林增量训练**：`voteCounts`（每样本各类投票数）与 `importanceSums`（各维度重要性累加）随树数递增，`treeCount` 记录已训练树数，每步只训练一棵新树。

### 4.3 学习引导模块

| 子模块 | 数据来源 | 说明 |
|---|---|---|
| 评估面板 | 训练响应 + `buildSimulation` | 指标卡（值、delta、方向色）+ 双轴曲线 |
| 模型解释 | `modelKind` 分支 | 树 → 节点图；线性 → 权重条形图；其余 → 摘要文案 |
| 训练日志 | 组件事件 | 最多 8 条，覆盖开始/首步/下降/收敛/完成 |
| 案例库 | `LearningGuideDataService.getGuidedCases()` | 5 个案例 + 引导阶段（idle/configured/running/verified） |

**指标卡设计要点**：`value` 允许为 `undefined`——训练未开始时只显示标签不显示数字，避免「0 步就显示 36% 准确率」的误导；`delta` 取相邻两步差值，`lowerIsBetter` 决定红绿方向。

**训练轨迹横轴固定为 `0..totalSteps`**：不同算法步数差别很大（决策树可能只有 5 步，梯度下降 100 步），固定横轴才能横向比较同一算法不同参数的收敛速度。

### 4.4 进阶模块

| 模块 | 实现方式 | 边界 |
|---|---|---|
| 模型对比 | 逐配置调用一次完整训练（`/comparison`），汇总最终指标 | 串行执行，配置多时耗时线性增长 |
| 特征工程 | 过滤列后重建临时数据集，做一次完整评估 | 只做单次评估，不做逐步训练 |
| AI 助手 | `WebClient` 调 OpenAI 兼容接口，上下文由前端组装 | 需外部 Key；超时/失败返回错误文案 |
| PCA 解释 | 前端由载荷矩阵推导主成分含义标签 | 规则启发式，不是语义模型 |

### 4.5 学习中心模块

| 子模块 | 设计 |
|---|---|
| 课程 | 8 节，硬编码在 `LearningComponent.lessons`，含 sections/keyPoints/example/checkQuestion |
| 随堂自测 | 每节 1 题内联，选择后即时判分并展开解析 |
| 理论考核 | 题库 40 个知识点 × 5 种问法 = 200 题（`createQuestionBank()` 生成），随机抽 5 题，每题 20 分 |
| 错题集 | 题 ID 集合持久化到 `localStorage`，可「只考错题」（不足 5 题时用随机题补足） |

题库用「一个知识点 + 5 个不同问法 + 干扰项轮换正确位置」的方式生成，保证同一知识点反复出现时不是同一道题，避免死记答案位置。

## 5. 核心算法设计

### 5.1 统一的数据抽象

所有算法共享两套数据装载：

| 抽象 | 装载内容 | 适用 |
|---|---|---|
| `DataMatrix`（`loadDataMatrix`） | 全维度特征矩阵 + 归一化 + 目标/类别编码 | 线性/逻辑回归、K-Means、决策树、随机森林、PCA |
| `DataSet2d`（`loadDataSet`） | 两维点集 + 统计量 | SVM（只做二维几何） |

`DataMatrix` 内部保存每个特征的 `min/max`（`range`），提供 `normalizeFeature / denormalizeFeature / normalizeTarget / denormalizeTarget`，因此算法内部一律在归一化空间计算，画图时再反归一化回原始单位。

### 5.2 线性回归

```
预测：ŷ = w·x + b（归一化空间）
损失：MSE = Σ(ŷ - y)² / n
更新：w ← w - lr · grad(w)，其中 grad 带 0.35 动量项
```

- 学习率 clamp 到 `[0.0001, 0.2]`，避免 UI 传入极端值导致发散；
- 评估时同时算归一化 MSE（曲线用）与原始单位的 R²（展示用），R² clamp 到 `[0, 0.99]`；
- 回归线由 `buildFullRegressionLine` 在所选两维的平面上重算，隐藏维度固定在均值处。

### 5.3 逻辑回归

```
z = w·x + b
p = sigmoid(z)
loss = -[y·log p + (1-y)·log(1-p)]
决策边界：w·x + b = 0
```

- `sigmoid` 分正负两支实现，避免 `exp` 溢出；
- 支持 `regularization` 参数（默认 0.01），以 L2 形式加入梯度；
- 边界绘制用 `buildFullLinearBoundary`：在二维平面上求 `w1x1 + w2x2 + b + Σ(其余维固定均值项) = 0` 的等值线。

### 5.4 决策树

```
1. 计算节点不纯度（gini 或 entropy）
2. 对每个候选 (特征, 阈值) 计算加权子不纯度，取下降最多者
3. 递归分裂，直到：达到 maxDepth / 样本数 < minSamplesSplit / 节点已纯
4. 整棵树一次性建完，按 BFS 记录 splitOrder
5. 训练一步 = revealedSplits + 1
```

评估：

- `loss` = 当前已展开部分的**样本占比加权不纯度**；
- `score` = 当前树在训练集上的准确率；
- 节点表同时服务于「树结构图」与「平面分区线」两种可视化。

### 5.5 随机森林

```
for each step:
    1. bootstrap 采样（有放回）
    2. 随机特征子集（sqrt(featureCount) 个）
    3. 训练一棵决策树（同样的贪心分裂）
    4. 该树对每个样本投票 → voteCounts 累加
    5. 树内不纯度下降按样本占比归一到 1 → importanceSums 累加
评估：多数投票 → 准确率；误差率作为 loss
```

- 树数 `n_estimators` clamp 到 `[1, 20]`，受单步耗时约束；
- 特征重要性 = `importanceSums / treeCount`，归一化后输出为条形图。

### 5.6 K-Means

```
初始化：随机选 K 个样本点作为质心（initMethod 参数保留，当前为随机）
循环：assignClusters（最近质心，归一化欧氏距离）
      → recomputeCentroids（簇内均值）
评估：Inertia（归一化）+ 近似轮廓系数
```

- 距离在归一化空间计算，避免大尺度特征主导；
- 质心保留全维度 `values`，`x/y` 只是它在默认两维上的取值，因此任意坐标轴都能正确投影；
- 轮廓系数用 `approximateSilhouette` 采样估算，避免 O(n²) 在浏览器等待时间内跑不完。

### 5.7 SVM

| 核 | 实现 |
|---|---|
| linear | `trainLinearSvm`：按梯度推挤 `w`、`b`，最大化间隔 |
| rbf | `trainRbfSvm`：以高斯核对样本加权打分，`gamma` 控制影响半径 |
| poly | `trainPolySvm`：`(γ·x·x' + 1)^d` 形式的多项式打分 |

SVM 是唯一**不做全维度训练**的算法：几何量（边界采样、支持向量）都建立在两维平面上，`projectModel` 对非训练维度返回 `kind = "none"` 并给出提示文案。

### 5.8 PCA

```
1. 取所有 number 类型维度构成矩阵
2. 按列中心化（记录均值 pcaMean）
3. 计算协方差矩阵，幂迭代求特征值与特征向量
4. 取前 k 个（k = clamp(n_components, 1, 3)）
5. 投影得到 pcaTransformed；同时输出 explained / cumulative
```

- 一次算完，`status = completed`，`currentStep = totalSteps = k`；
- 保留 `pcaMean`，是为了让投影可逆、也便于解释「中心化」这一步；
- 前端按 `n_components` 选择 2D 散点或 3D 散点；3D 视图由 `VisualizationCanvasComponent` 使用原生 Canvas 2D 自行绘制并支持拖拽旋转，不依赖 ECharts GL / WebGL。

### 5.9 算法能力对照

| 算法 | 训练维度 | 步进 | loss 标签 | score 标签 | 主要可视化 |
|---|---|---|---|---|---|
| 线性回归 | 全维度 | 梯度步 | MSE | R2 | 回归线、权重条形图 |
| 逻辑回归 | 全维度 | 梯度步 | Loss | Accuracy | 决策边界、权重条形图 |
| 决策树 | 全维度 | 一次揭示一个分裂 | Gini/不纯度 | Accuracy | 树结构、二维平面分区线段 |
| 随机森林 | 全维度 | 一次训练一棵树 | Error | Accuracy | 特征重要性；样本按预测类别着色，不绘制二维决策分区线 |
| K-Means | 全维度 | 一轮「样本分配 + 质心更新」 | Inertia | 近似 Silhouette | 质心、簇着色 |
| SVM | 两维 | 一次迭代 | Hinge Loss | Accuracy | 边界、支持向量摘要 |
| PCA | 全维度 | 一次算完 | — | ExplainedVar | 2D/3D 投影、载荷矩阵 |

## 6. 关键设计决策

### 6.1 全维度训练 + 按需投影（而不是先降维再训练）

**问题**：iris 有 4 维、boston 有 13 维，画布只有二维。常见做法是「取前两列训练」，但这会让模型与可视化错位——用户看到的线是两维模型的线，切换坐标轴就完全失效。

**方案**：模型在全维度上训练，可视化时由 `projectModel` 求「该二维平面上的模型切片」：

- 线性模型：把隐藏维度固定在均值处，得到平面上的直线（数学上就是等值线的截线）；
- K-Means：直接投影全维度质心；
- 决策树：沿树收集与所选平面相交的轴对齐分区线段；随机森林虽然使用全维度特征训练，但当前不生成二维决策分区线，只按样本预测类别着色；
- SVM：不参与投影，切维度时明确提示「该算法只在两维上训练」。

**收益**：任意切换坐标轴，看到的都是真实模型在该平面上的行为；**代价**：多一次投影请求，且 SVM 的能力边界对用户可见。

### 6.2 模型快照存库（而不是内存持有）

服务端不保存任何会话对象，全部塞进 `training_session.model_data`。好处是重启、换实例、浏览器刷新后都能续训；代价是每步一次 JSON 序列化 + UPDATE。教学场景步数在百级，可接受。

### 6.3 决策树一次建树 + 逐步揭示

一次建完树再逐步「揭示」分裂，而不是每步真正重新分裂：结果确定、可复现，且暂停时模型精确停在「最近一次分裂」的状态。这也是「单步训练」在决策树上唯一可行的实现方式——真正的增量建树必须缓存待分裂队列，复杂度收益不成比例。

### 6.4 前端双模式（API / Mock）

`environment.demoMode` 控制默认走哪条路；即使为 `false`，一旦目录接口失败也会自动切 mock 并提示。教学项目需要「一定能演示」——评审时后端没起、数据库没通，界面仍然完整可用（指标是合成的，会明确提示）。

### 6.5 路由保活

Angular 默认离开路由就销毁组件，训练定时器、课程进度、答题状态都会丢。`KeepAliveRouteReuseStrategy` 把 `experiment`、`learn` 的 `DetachedRouteHandle` 缓存在 `Map` 里，返回时复用同一实例。

副作用与对策：

| 副作用 | 对策 |
|---|---|
| 组件不销毁，ECharts 容器尺寸失效 | 回到路由时 `dispatchEvent(new Event('resize'))` |
| 滚动位置丢失 | `NavigationStart` 时记录 `window.scrollY`，回来再还原 |
| 订阅不会自动清理 | 组件仍在 `ngOnDestroy` 里 `unsubscribe`，并在策略变更时手动处理 |

### 6.6 幂等的数据初始化

`DatasetSeedInitializer` 只在「条数不足」时填充，且任何失败只降级不阻断。这样 `docker compose up` 反复执行、数据库卷保留旧数据、离线环境，三种情况都不会让应用起不来。

## 10. 扩展性设计

### 10.1 新增算法

1. `algorithm` 表加记录（`name` 唯一，参数 JSON 定义 UI）；
2. 实现 `trainXxx` + `evaluateXxx`；
3. 在 `trainAlgorithmStep`、`evaluateCurrentState`、`initializeModelData` 三处分派登记；
4. 若是新损失/得分口径，更新 `getLossLabel`；
5. 前端零改动即可用（参数面板自动生成，画布按 `modelKind` 分支）；
6. 新算法若只在两维训练，加入 `isFullDimensionAlgorithm` 排除名单。

### 10.2 新增数据集

1. `dataset` 表插入记录，`features` 声明维度；
2. 需要自动补齐则登记到 `dataset-seed.remote-sources` 或 `synthetic-samples`；
3. CSV 表头必须与 `features[].name` 一致。

### 10.3 新增页面

1. 组件登记到 `app.module.ts` 的 `declarations`；
2. 路由加到 `app-routing.module.ts`；
3. 需保活则把 `path` 加进 `KEEP_ALIVE_PATHS`，并处理尺寸/滚动还原。

### 10.4 已知技术债

| 项 | 影响 | 建议 |
|---|---|---|
| 三处 `if` 分派 | 新增算法易漏改，导致「能训练不能评估」 | 抽出策略接口 + `Map` 注册表 |
| `TrainingSimulationService` 3146 行 | 单测成本高、认知负担大 | 按算法拆成独立策略类 |
| `file_name` / 上传接口半成品 | CSV 上传不可用 | 补 CSV 解析（复用 `DatasetSeedInitializer.parseCsv`） |
| `predict` / `model-structure` 占位 | 接口文档与实际能力不符 | 实现或从文档移除 |
| CSS 变量与内联色值混用 | 主题切换困难 | 收敛到 `styles.scss` 的 CSS 变量 |

### 3.1 启动类与容器初始化

### 3.2 Controller 层

统一返回 `ApiResponse<T>`，参数校验失败与业务异常由 `GlobalExceptionHandler` 转成 `400/500`。

#### 3.2.1 AlgorithmController（`/api/algorithms`）

### 3.3 Service 层

#### 3.3.1 TrainingSimulationService（核心）

**对外方法**

| 方法 | 作用 |
|---|---|
| `startTraining(Long algorithmId, Long datasetId, String parameters)` | 建会话、初始化模型、写第 0 步指标 |
| `stepTraining(Long algorithmId, Long sessionId, Long datasetId, String parameters)` | 取会话 → 校验归属 → 恢复模型 → 训练一步 → 落库 |
| `pauseTraining(Long algorithmId, Long sessionId)` | 只重新评估，不推进步数 |
| `getModelData(Long sessionId)` | 读取快照，缺失则重建 |
| `getMetrics(Long sessionId)` | 读取指标历史，缺失则现算一个点 |
| `projectModel(Long sessionId, String xName, String yName)` | 生成任意两维的模型切片 |
| `startPca(Long algorithmId, Long datasetId, String parameters)` | PCA 一次性计算（1~3 个主成分） |
| `startRandomForest(Long algorithmId, Long datasetId, String parameters)` | 一次性训练完整森林 |
| `simulateFeatureSelection(Long, Long, List<String>, String)` | 过滤特征后做一次完整评估 |

**内部算法方法**（均为 `private StepResult xxx(Dataset, String parameters, ModelData)`，不依赖数据库，便于单测）

| 算法 | 训练一步 | 评估 |
|---|---|---|
| 线性回归 | `trainLinearRegression`（带 momentum 的梯度下降） | `evaluateLinearRegression`（归一化 MSE + R²） |
| 逻辑回归 | `trainLogisticRegression` | `evaluateLogisticRegression`（交叉熵 + Accuracy） |
| K-Means | `trainKMeans`（分配 + 重算中心） | `evaluateKMeans`（归一化 Inertia + 近似轮廓系数） |
| 决策树 | `trainDecisionTree`（revealedSplits + 1） | `evaluateDecisionTree`（加权不纯度 + Accuracy） |
| 随机森林 | `trainRandomForestStep`（加一棵树） | `evaluateRandomForest`（投票 + Error） |
| SVM | `trainSvm` → `trainLinearSvm / trainRbfSvm / trainPolySvm` | `evaluateSvm` → `evaluateKernelSvm / evaluateLinearSvm` |

**分派逻辑**（新增算法时要同步改这里）

```java
private StepResult trainAlgorithmStep(Algorithm algorithm, Dataset dataset,
                                      String parameters, ModelData modelData) {
    String name = algorithm.getName() == null ? "" : algorithm.getName();
    String type = algorithm.getType() == null ? "" : algorithm.getType();

    if ("linear_regression".equals(name))            return trainLinearRegression(...);
    if ("logistic_regression".equals(name))          return trainLogisticRegression(...);
    if ("kmeans".equals(name) || "clustering".equals(type)) return trainKMeans(...);
    if ("decision_tree".equals(name))                return trainDecisionTree(...);
    if ("random_forest".equals(name))                return trainRandomForestStep(...);
    if ("svm".equals(name))                          return trainSvm(...);
    if ("classification".equals(type))               return trainLogisticRegression(...);
    if ("regression".equals(type))                   return trainLinearRegression(...);
    return evaluateCurrentState(algorithm, dataset, parameters, modelData);
}
```

`evaluateCurrentState` 是第二处同构分派，`initializeModelData` 是第三处。新增算法必须同时改三处，否则会出现「能训练但不能评估」。

#### 3.3.2 训练会话与步数

```java
int totalSteps = getTotalStepsFromParameters(parameters, algorithm);
```

| 情况 | 步数 |
|---|---|
| 有 `iterations` | 取该值，clamp 到 `[10, 1000]` |
| 有 `maxIterations`（K-Means） | 同上 |
| `decision_tree` | 先按 `maxDepth * 2`，建树后回填为**实际分裂数** `countSplits(tree)` |
| `random_forest` | `n_estimators`，clamp 到 `[1, 20]` |
| 其他 | `DEFAULT_TOTAL_STEPS = 100` |

会话状态机：

```
status: idle → training → paused → completed
currentStep: 0 .. totalSteps
```

- `stepTraining` 里 `nextStep = min(totalSteps, currentStep + 1)`，`nextStep >= totalSteps` 时置 `completed`；
- `pauseTraining` 不推进步数，只把当前步的指标点覆盖为最新评估（`upsertMetricPoint`）；
- 第 0 步的基线点由 `startTraining` 写入，因此曲线从 0 开始。

```java
// 存档（每次 step / pause 之后）
```

#### 3.3.5 全维度模型与投影

```java
private boolean isFullDimensionAlgorithm(String name, String type) {
    if ("svm".equals(name)) return false;         // SVM 仍只在两维上训练
    return "linear_regression".equals(name) || "logistic_regression".equals(name)
        || "kmeans".equals(name) || "decision_tree".equals(name)
        || "random_forest".equals(name)
        || "regression".equals(type) || "classification".equals(type) || "clustering".equals(type);
}
```

- 全维度算法在 `ModelData` 里记录 `modelKind`、`featureNames`、`targetName`、`classNames`，权重/质心按全部维度保存；
- `projectModel` 按请求的两维重新求切片：线性模型把隐藏维度固定在均值处，得到一条直线；K-Means 直接投影质心；决策树沿树收集轴对齐的分区线段；
- SVM 只在两维训练，请求维度不等于训练维度时返回 `kind = "none"` 并附带 `note` 说明，前端据此显示提示而不是画错误的线。

#### 3.3.6 DatasetService

| 方法 | 说明 |
|---|---|
| `getAllDatasets()` / `getDatasetsByCategory()` | 列表版 DTO |
| `getDatasetById()` | 详情版 DTO（含 `dimensions`、`values`） |
| `createDataset(Dataset)` | 写库后回读 |
| `getDataPoints(Long id)` | 仅返回投影后的点 |

坐标轴选择策略（`buildProjection`）：标签列由 `features[].type == "label"` 识别；X 轴优先 `rm / x / petal_length / sepal_length`，Y 轴优先 `y / petal_width / sepal_width`；找不到则退化为前两个数值列。

#### 3.3.7 AlgorithmService

- `convertToDTO` 把 `parameters` 的 JSON 文本解析为 `List<ParameterDef>`，解析失败时返回空列表（不抛异常，保证列表接口可用）；
- `normalizeParameterNames` 会把 SVM 的历史参数名 `C` 改写为 `c`，与 `schema.sql` 及前端保持一致。

#### 3.3.8 AiAssistantService

- 用 `WebClient` 调 OpenAI 兼容接口（`llm.endpoint` + `/chat/completions`）；
- `buildSystemPrompt` 固定角色设定；`buildUserPrompt` 把算法、数据集、训练状态、当前指标、参数拼成上下文；
- `extractContent` 从 `choices[0].message.content` 取值；
- 未配置 `llm.api-key` 时直接返回错误提示，不发起请求。

#### 3.3.9 DatasetSeedInitializer

`ApplicationRunner`，启动时执行一次：

1. `dataset-seed.enabled = false` 时直接跳过；
2. 遍历 `dataset-seed.remote-sources`：查库 → 条数不足才下载 CSV → 按 `features` 表头对齐解析 → `saveRows`；
3. 遍历 `dataset-seed.synthetic-samples`：条数不足才生成 `make_classification`（两个高斯簇）/ `make_blobs`（三个高斯簇）；
4. 任何异常只记日志，绝不阻断启动。

代理解析优先级：`DATASET_SEED_PROXY` → `HTTPS_PROXY/https_proxy/HTTP_PROXY/http_proxy` → `dataset-seed.proxy-host/port`。

**TrainingSimulationResponse 结构**（前端全部可视化数据都从这里来）

```java
class TrainingSimulationResponse {
    Long sessionId; Long algorithmId; Long datasetId;
    String status; Integer currentStep; Integer totalSteps;
    Double loss; Double accuracy; String scoreLabel;
    Metrics metrics; ModelData modelData;

    class Metrics { List<MetricPoint> points; String lossLabel; String scoreLabel; }
    class MetricPoint { Integer step; Double loss; Double score; }

    class ModelData {
        List<List<Double>> decisionBoundary;   // 决策边界折线
        List<List<Double>> regressionLine;     // 回归线
        List<Centroid> centroids;              // 聚类中心（含全维度 values）
        List<Double> weights; Double bias;
        String modelKind;                      // linear_regression / kmeans / decision_tree / ...
        List<String> featureNames; String targetName; List<String> classNames;
        List<TreeNode> tree; Integer revealedSplits;    // 决策树 + 已展开分裂数
        List<List<Integer>> voteCounts; List<Double> importanceSums; Integer treeCount;  // 随机森林
        List<Integer> assignments;
        String splitFeature; Double splitThreshold; Double splitImpurity;
        List<List<Double>> pcaComponents; List<List<Double>> pcaTransformed;
        List<Double> pcaExplainedVariance; List<Double> pcaCumulativeVariance; List<Double> pcaMean;
        List<FeatureImportance> featureImportances;
    }
    class TreeNode { Integer id; Integer depth; String feature; Integer featureIndex; Double threshold;
                     Double impurity; Integer samples; Integer classIndex;
                     Integer leftId; Integer rightId; Integer splitOrder; }
}
```

### 4.3 训练中心的训练循环

```typescript
onStartTraining() {
  // 1. 暂停态：直接续训
  if (this.trainingState.status === 'paused' && this.trainingState.sessionId) return this.onResumeTraining();
  // 2. PCA：一次性请求
  if (this.isPcaAlgorithm) return this.runPca();
  // 3. 其余：先建会话，再起 850ms 定时器
  const version = this.clearTrainingTimer();
  this.apiService.startTraining(...).subscribe(res => {
    if (!this.isCurrentRequest(version)) return;
    this.applyTrainingResponse(res.data);
    const v = this.startContinuousTraining();
    this.requestTrainingStep(false, v);
  });
}
```

**防竞态三件套**

| 机制 | 作用 |
|---|---|
| `requestVersion` | 每次开始/暂停/重置自增，旧响应回来直接丢弃 |
| `stepInFlight` | 上一步请求未返回时不再发下一步，避免步数跳变 |
| `sessionId` 校验 | `isCurrentRequest(version, sessionId)` 同时校验版本与会话 |

**单步与连续的差异**：`requestTrainingStep(singleStep, version)` 的 `singleStep = true` 时，成功推进一歩后把状态置为 `paused`；连续模式不改状态，靠定时器驱动。

```typescript

  private static readonly KEEP_ALIVE_PATHS = new Set<string>(['experiment', 'learn']);
```

- 训练中心保活的原因：训练由组件内的 `setInterval` 驱动，路由销毁会清掉定时器并重置进度；
- 学习中心保活的原因：当前课节、视图、作答、进度都是组件字段，销毁即回到初始课节。

保活带来的副作用必须处理：组件不会被销毁，`ngOnDestroy` 里的 `unsubscribe` 不一定触发；同时视图脱离文档后 ECharts 尺寸会失效。`ExperimentComponent` 因此订阅 `router.events`，回到 `/experiment` 时派发一次 `resize`；`LearningComponent` 在 `NavigationStart` 时记录 `window.scrollY`，回来后再还原。

### 4.8 PCA 主成分含义标签

`utils/pca-labels.ts` 的 `describePcaComponents` 从载荷矩阵推导每个主成分的短标签：

1. 取 `|载荷| >= 0.35` 的前 3 个特征为主导特征（都被过滤时保留第一名）；
2. 主导特征名按 `_ / 空格 / -` 切词求公共前缀作为概念名（`petal_length` + `petal_width` → `petal`）；
3. 全同号 → 「正向综合轴」，正负混合 → 「对比轴」，只有一个 → 「主导轴」；
4. 生成 `shortLabel`（坐标轴/徽章用）与 `description`（“主要由 petal_length(+0.86)、petal_width(+0.36) 构成…”）。

## 7. 扩展指南

### 7.1 新增算法

1. `schema.sql` 追加一行 `algorithm`（或在启动类 `ensureAlgorithms` 里补）；
2. `TrainingSimulationService` 中新增 `trainXxxStep` 与 `evaluateXxx`；
3. 在 `trainAlgorithmStep`、`evaluateCurrentState`、`initializeModelData` **三处**分派中登记；
4. 需要新的损失标签时改 `getLossLabel`；
5. 前端一般无需改动：参数面板按 `parameters` 自动渲染，画布按 `modelKind` 选择渲染分支；
6. 若新算法不是全维度模型，把它加入 `isFullDimensionAlgorithm` 的排除名单。

### 7.2 新增数据集

1. 在 `dataset` 表插入记录，`features` 声明维度，`data_content` 可先放少量演示数据；
2. 想让启动时自动补齐，就在 `dataset-seed.remote-sources`（远程 CSV）或 `synthetic-samples`（程序生成）里登记；
3. 表头必须与 `features` 的 `name` 完全一致，否则该数据集会被跳过并打日志。

### 7.3 新增页面

1. 新建组件并在 `app.module.ts` 的 `declarations` 中登记；
2. 在 `app-routing.module.ts` 加路由；
3. 需要保留页面状态时，把路由 `path` 加入 `KeepAliveRouteReuseStrategy.KEEP_ALIVE_PATHS`，并在组件里处理「重新挂载后」的尺寸/滚动还原。

## 9. 代码规范

- 后端：Controller 只做参数搬运，业务在 Service；`Repository` 只写 SQL；异常统一抛 `IllegalArgumentException`（→400）或让其冒泡（→500）。
- 后端：DTO 与实体分离，实体不直接返回给前端（`Algorithm` / `Dataset` 都有对应 DTO）。
- 前端：组件只处理视图与交互，HTTP 一律走 `ApiService`；跨组件共享状态放 `ExperimentContextService`。
- 前端：TypeScript 严格类型，`TrainingState['status']` 用联合类型收口，避免非法状态。
- 命名：Angular 文件 `xxx.component.ts / xxx.service.ts`，Java 类 `XxxController / XxxService / XxxRepository`。
